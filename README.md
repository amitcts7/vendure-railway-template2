up a **Vendure v3.5.5** instance populated with test data, including the new **React Dashboard** and

## Directory structure

* `/src` contains the source code of your Vendure server. All your custom code and plugins should reside here.
* `/static` contains static (non-code) files such as assets (e.g. uploaded images) and email templates.
* `/dist` contains the compiled output (generated by `npm run build`, gitignored except `dist/dashboard/`).

## Development

```bash
npm run dev
```

Starts the Vendure server and [worker](https://www.vendure.io/docs/developer-guide/vendure-worker/) processes
concurrently from the `src` directory using `ts-node`.

Or run them separately:

```bash
npm run dev:server   # API server only
npm run dev:worker   # job queue worker only
```

## Build

```bash
npm run build
```

Compiles the TypeScript sources into the `/dist` directory.

The React Dashboard is pre-built via GitHub Actions and the output (`dist/dashboard/`) is committed
to the repository. Railway uses this pre-built output directly — no dashboard build step runs on Railway.

To rebuild the dashboard locally:

```bash
npm run build:dashboard
```

## Deployment on Railway

This template uses **[Railpack](https://railpack.io)** — Railway's native builder — for fast, cached builds.

- Railway detects Node.js automatically
- Runs `npm install` and `npm run build` (`tsc` only — ~30 seconds)
- Starts with `node ./dist/index.js`
- `node_modules` is cached between deploys

See [RAILWAY_SETUP.md](./RAILWAY_SETUP.md) for the complete step-by-step deployment guide including
PostgreSQL, asset storage (MinIO / S3 / Railway Volume), worker service, and publishing as a template.

## Available endpoints

**Backend service:**

| URL | Description |
|---|---|
| `/dashboard` | React Dashboard (admin UI) |
| `/admin-api` | Admin GraphQL API |
| `/shop-api` | Storefront GraphQL API |
| `/assets` | Asset server |

**Storefront service** (separate Railway service from [nextjs-starter-vendure](https://github.com/vendurehq/nextjs-starter-vendure)):

| URL | Description |
|---|---|
| `/` | Next.js storefront (product browsing, cart, checkout) |
| `/account` | Customer account (orders, addresses, profile) |

## Production (non-Railway)

Run the compiled output directly:

```bash
npm run start         # server + worker (concurrent)
npm run start:server  # server only
npm run start:worker  # worker only
```

You could also consider using a process manager like [pm2](https://pm2.keymetrics.io/) to run and manage
the server & worker processes.

## Plugins

In Vendure, your custom functionality will live in [plugins](https://www.vendure.io/docs/plugins/).
These should be located in the `./src/plugins` directory.

## Migrations

[Migrations](https://www.vendure.io/docs/developer-guide/migrations/) allow safe updates to the database schema.
Migrations will be required whenever you make changes to the `customFields` config or define new entities in a plugin.

```bash
npx vendure migrate
```

The generated migration file will be found in the `./src/migrations/` directory and should be committed to source
control. Outstanding migrations are run automatically on each server start by the `runMigrations()` function in
[src/index.ts](./src/index.ts).

> If during initial development you do not want to manually generate migrations on each `customFields` change,
> set `dbConnectionOptions.synchronize` to `true`. This is **not** recommended once you have production data.
